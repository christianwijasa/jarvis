# PRD self-check before review

Answer each question before you show the draft to the owner.

## Content

- [ ] The problem names who has it and the evidence.
- [ ] Each goal has a metric, a baseline, a target, and how it is measured.
- [ ] "Out of scope" lists at least one thing.
- [ ] Each flow is a numbered list of user steps.
- [ ] Each business rule is one testable sentence with an ID.
- [ ] Each acceptance criterion is Given / When / Then and names its rule or step.
- [ ] Edge cases cover empty, invalid, duplicate, late, and permission cases where they apply.
- [ ] Rollout says who gets it first and what makes us roll back.
- [ ] Settled decisions are in "Decisions" with a date and who decided.
- [ ] Questions about current system behavior are in "Engineering checks", not answered by guess.

## Form

- [ ] No placeholder text or scaffold note is left.
- [ ] Empty optional sections are removed.
- [ ] No architecture, service names, or database design.
- [ ] New terms are in the glossary, and the PRD uses the same words.
- [ ] Frontmatter has the work-item key in `issue:` and the right `status`.
- [ ] The document does not name the planning tool.
